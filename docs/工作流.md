# 小組工作流：Issue → Branch → Pull Request → Review → Merge

把「做東西 → 被檢查 → 修改 → 成為正式版本」變成固定流程。

## 1. 開 Issue（記錄要做的事或 Bug）

- **🐞 Bug 回報**：測試者 D 發現問題就開，寫清楚「重現方式／預期結果／實際結果」。
- **✅ 任務**：企劃 A 把 Notion 每週目標拆成一張張任務。
- 指派負責人（Assignees），一張 Issue 只做一件事。

## 2. 開 Branch（在自己的分支上改）

網頁上：Issue 右側 **Development → Create a branch**，或在 Code 頁切換分支輸入新名稱。
命名建議：`fix-12-start-button`、`feat-15-moisture-chart`（類型-Issue 編號-簡述）。

## 3. 開 Pull Request（請組員檢查）

- 改完後按 **Compare & pull request**。
- 內文照範本填：改了什麼、對應哪個 Issue（寫 `Closes #12` 會自動關閉）、怎麼測試、AI 幫了什麼、你怎麼驗證。

## 4. Review（同儕檢查）

- 至少一位組員看過再合併：程式能跑嗎？有沒有解決 Issue？命名清楚嗎？
- 有問題就在程式碼行上留言，作者修改後再推上同一個分支。

## 5. Merge（成為正式版本）

- 通過後按 **Merge pull request**，GitHub Pages 會在 1–2 分鐘內更新。
- 回到 Notion「每週進度」記一筆：這週合併了哪些 PR、學到什麼。

## 每週節奏

| 時間 | 做什麼 | 平台 |
|---|---|---|
| 課堂開始 | 對齊本週目標，拆成 Issue | Notion → GitHub |
| 課堂中 | Branch 開發、測試、開 Bug | GitHub |
| 課堂結束前 | PR → Review → Merge | GitHub |
| 課後 | 每週打卡＋反思 | 課程專題工作流（打卡）＋ Notion（反思） |
